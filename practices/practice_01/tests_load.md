# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Baseline: короткие diff, LLM ok | 10→50 RPS, 3–5 минут, локальная заглушка LLM (ok) | p95 < 1s при 10 RPS; p95 < 1.5s при 50 RPS | p50/p95/p99 латентности, доля 2xx, структура OUT-1 (risks ≤ 3) | OUT-1 (context.md); ADR «Решение» |
| Fast-path 422 | 50 RPS, 1 минута, запросы без `diff` | Время ответа < 100ms; 0 вызовов LLM | Латентность 422, счётчик обращений LLM | Вход (context.md); product_management.md; ADR «Решение» |
| Fast-path 413 | 50 RPS, 1 минута, `diff` длиной 20 001 | Время ответа < 100ms; 0 вызовов LLM | Латентность 413, счётчик обращений LLM | API-1 (context.md); ADR «Решение» |
| Stress: таймауты LLM | 20–30 RPS, 2–3 минуты; 10–20% запросов → sleep ≥10s | Доля 504 ≈ доле таймаутов; p95 успешных < 2s; timeout ~10s ± допуск | Распределение кодов (2xx/504), латентности по классам | REL-1 (context.md); ADR «Маппинг ошибок LLM → HTTP» |
| Stress: сетевые/5xx ошибки | 20–30 RPS, 2–3 минуты; 10–20% запросов → 5xx/NetworkError | Доля 502 ≈ доле отказов; нет лавинообразных ретраев (>x3) | Распределение кодов (2xx/502), среднее число попыток ≤ 3 | ADR «Решение (ретраи x3 с jitter)», «Маппинг ошибок» |
| Spike: всплеск нагрузки | Удвоение baseline на 30–60с | Нет деградации > установленных p95; без очередей/stop-the-world | p95/пул воркеров/эвент-луп, ошибки | ADR «Решение (async)» |
| OBS-1 под нагрузкой | Выборочная проверка логов в baseline/stress | В логах только request_id, длительность, статус; нет diff/prompt/response | Сэмплы логов по профилям | OBS-1 (context.md); ADR «Политика логирования» |
| Ретраи под нагрузкой | Stress-профиль с 20% отказов | Не более 3 попыток на запрос; нет превышения x3 | Счётчик попыток по запросам | ADR «Решение (ретраи x3 с jitter)» |
| Ресурсы и устойчивость | Baseline 5 минут; Stress 3 минуты | Нет роста RSS/CPU трендом; без утечек | CPU, RSS процесса; метрики пула/цикла | Эксплуатационная пригодность; ADR «Решение» |
