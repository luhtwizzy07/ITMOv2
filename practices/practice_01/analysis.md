# Анализ процесса: AS IS и TO BE

## AS IS

Клиент шлёт POST /api/reviews с JSON dict → FastAPI обработчик читает payload["diff"] → ReviewService формирует текстовый prompt с полным diff → вызывает llm.generate(prompt) без таймаута/ограничений → возвращает {"comment": answer}. 

Участники: Клиент API, FastAPI, ReviewService, внешний LLM. Задержки: сетевой вызов LLM без таймаута (риск зависания). Потери: нет фильтрации секретов (SEC-1), нет ограничений на размер diff (API-1), отсутствие контролируемых ошибок (REL-1).


## TO BE

Добавить валидацию входа (модель с полем diff, max_length ≤ 20000), фильтрацию секретов перед вызовом LLM, таймаут и обработку ошибок. Возвращать структурированный ответ {summary, risks[], checks[]} по OUT-1.

```mermaid
flowchart LR
    A[POST /api/reviews] --> B[Валидация diff <= 20k]
    B --> C[Секреты удалены SEC-1]
    C --> D[LLM.generate с таймаутом <= 10s]
    D --> E[Контролируемая обработка ошибок]
    E --> F[Ответ OUT-1: summary, risks, checks]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Контракт входа | dict без схемы | Модель с diff и max_length | Интеграционный тест 422 и 413 |
| Защита секретов | Нет | Маскирование перед LLM | Юнит-тест фильтра и snapshot промпта |
| Надежность LLM | Без таймаута/обработки | Таймаут 10s и маппинг ошибок | Тесты отказов и метрики |
| Контракт ответа | {comment} | {summary, risks, checks} | E2E на структуру ответа |
