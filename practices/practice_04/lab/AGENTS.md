# Правила Notify Mini

- Рабочая директория — эта папка lab, а не корень учебного репозитория.
- До изменения кода прочитай docs/requirements.md и docs/style-guide.md.
- Пример тестов: tests/test_baseline.py. Не меняй существующий контракт subscribe.
- Для новых фич загрузи skill notify-tdd и прочитай его references/test-cases.md.
- Единый runner: sh scripts/check.sh all. Профили baseline, a и b — для этапов.
- MCP notify_checks предоставляет project_check(profile): используй его для
  проверки результата; произвольные команды и пути через tool не передаются.
- После правки инструментами edit/write/apply_patch hook запускает тот же runner.
  FAIL означает необходимость разобраться, даже если инструмент записи успешен.
- Перед приёмкой просмотри diff и выполни git diff --check.
- Коммиты, создание веток и объединение выполняет управляющая сессия отдельно.
  Из OpenCode не запускай git commit, push или merge.
- Не изменяй материалы других практик, настройки hook и runner ради зелёных тестов.
- Сервис хранит состояние только в памяти процесса. Не обещай сохранение на диск.
