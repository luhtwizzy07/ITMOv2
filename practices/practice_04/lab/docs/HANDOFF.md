# Передача Notify Mini

## Состояние

Реализованы A — list_subscribers() и B — unsubscribe(name). Существующий
subscribe(name) сохранён. Все имена чувствительны к регистру, пробелы по краям
обрезаются; пустые имена отклоняются. Список отсортирован и не связан с внутренним
множеством. Повторная отписка возвращает false. Данные только в памяти процесса.

## Источники истины

Прочитай AGENTS.md, docs/requirements.md и docs/style-guide.md. Реализация —
service.py, тесты — tests/. REPORT.md связывает требования практики и ДЗ с
файлами evidence/. reflection.md содержит наблюдения по реальному выполнению.

## Воспроизведение

Работай из practices/practice_04/lab. В новом checkout выполни make setup:
worktree не переносит .venv. Затем make test и make mcp-proof.
Полная проверка — sh scripts/check.sh all; baseline/a/b доступны отдельно.
MCP notify_checks_project_check(profile) запускает тот же runner. Неизвестный
профиль и неверный тип — ошибки tool, а упавшие тесты дают статус FAIL.

OpenCode 1.18.31, локальная Ollama-модель itmo-agent, конфигурация opencode.json
в этой папке. Запускай с явным --model ollama/itmo-agent. Ключи не требуются.
Для 2.x сначала мигрируй MCP-конфигурацию и plugin API; примеры на слайдах 2.0.20
не совместимы с текущим конфигом. Skill notify-tdd уже включён в проект.

## Проверенные ограничения

- Нет БД, HTTP API, сохранения после перезапуска и обработки конкурентных запросов.
- Hook срабатывает после инструментов edit/write/apply_patch/multiedit OpenCode;
  это не универсальный файловый watcher и не проверка любой ручной shell-правки.
- Перед приёмкой всегда запускается общий runner независимо от hook.
- Отдельный worktree разделяет файлы и ветку, но не сервер Ollama и не порты.
- opencode.json явно исключён из игнорирования Git в lab/.gitignore: без этого
  среда оказалась неполной в новом worktree.
