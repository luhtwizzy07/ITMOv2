# Notify Mini: требования практики №4

Основа — учебный сервис из практики №3. Эта копия развивается независимо:
исходные материалы №3 не изменяются. Python 3.10+, стандартная библиотека для
продуктового кода; официальный MCP SDK нужен только для инструментов среды.

## Существующий контракт

`subscribe(name)` обрезает пробелы по краям, добавляет непустое имя в множество
`subscribers`, возвращает `{"subscribed": true}`. Пустое имя вызывает
`ValueError("empty name")`; повторная подписка не создаёт дубликат. Имена
чувствительны к регистру. Данные живут в памяти процесса, без сохранения на диск.

## Фича A: список подписчиков

`list_subscribers() -> list[str]` возвращает новый список имён, отсортированный
обычным порядком Python `sorted`. Для пустого множества результат `[]`.
Изменение возвращённого списка не меняет внутреннее множество. Подписка
сохраняет прежнее поведение. Приёмка: `sh scripts/check.sh a` и `baseline`.

## Фича B: отписка

`unsubscribe(name: str) -> dict[str, bool]` обрезает пробелы по краям.
Если имя существует, удаляет только его и возвращает `{"unsubscribed": true}`.
Если имени нет (включая повторный вызов), возвращает `{"unsubscribed": false}`.
Пустое имя вызывает `ValueError("empty name")` и не меняет состояние.
После отписки список A показывает актуальное состояние; повторная подписка
работает. Приёмка: `sh scripts/check.sh all` после объединения A и B.

## Границы задачи

Не добавлять БД, HTTP API, асинхронность или сторонние зависимости в service.py.
Не менять контракт subscribe и не ослаблять тесты ради успешной проверки.
Проверки должны изолировать состояние через subscribers.clear().
