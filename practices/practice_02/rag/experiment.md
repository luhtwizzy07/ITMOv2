## Запрос

Сгенерируй список нагрузочных профилей и метрик для `tests_load.md`, согласованных с ADR и правилами: baseline/stress/spike, fast-path 422/413, проверка ретраев ≤x3 и маппинга 504/502, проверка OBS-1 под нагрузкой, подтверждение структуры OUT-1, и метрики ресурсов (CPU, RSS). Укажи допустимые пределы p95/p99 по профилям и что считается успешным.

## Ответ со ссылками на источники

1) Профили нагрузки: baseline 10–50 RPS (p95 < 1–1.5s) с локальной заглушкой LLM [ADR «Решение» (async); OUT-1 в context.md].
2) Fast-path 422/413: ответ < 100ms, 0 вызовов LLM [product_management.md; API-1 и входной контракт в context.md; ADR «Решение»].
3) Stress (таймауты): 10–20% таймаутов → 504, тайминг ~10s; p95 успешных < 2s [REL-1 в context.md; ADR «Маппинг ошибок»].
4) Stress (5xx): 10–20% 5xx → 502; ретраи не более x3 на запрос [ADR «Решение (ретраи x3 с jitter)», «Маппинг ошибок»].
5) Spike: кратковременное удвоение нагрузки без выхода p95 за порог; без насыщения пула [ADR «Решение (async)»].
6) OUT-1 под нагрузкой: структура ответа валидна; risks ≤ 3 [OUT-1 из context.md; tests_e2e.md].
7) OBS-1 под нагрузкой: логи содержат только request_id, длительность, статус; нет diff/prompt/response [ADR «Политика логирования», OBS-1 из context.md; tests_integration.md].
8) Ресурсы: отсутствие тренда роста CPU/RSS [эксплуатационная пригодность из ADR «Решение»].
